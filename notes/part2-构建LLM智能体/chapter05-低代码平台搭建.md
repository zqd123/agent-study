# 第五章 基于低代码平台的智能体搭建

> 对应教程：`hello-agents/docs/chapter5/第五章 基于低代码平台的智能体搭建.md`
> 学习日期：2026-10-20
> 状态：了解即可 ✅

## 🎯 本章目标

- 理解低代码平台适合什么场景
- 建立平台化开发与自研开发的选型意识
- 不要求完整复刻 Coze / Dify / FastGPT / n8n 四个案例

## 📖 核心概念

| 概念 | 解释 | 我的理解 |
| ---- | ---- | -------- |
| 低代码平台 | 通过可视化节点、配置和提示词组装 Agent 的平台 | 把第四章的手写循环图形化，优点是快，缺点是复杂逻辑和版本管理弱 |
| 可视化编排 | 用节点和连线表达 Agent 工作流 | LLM 节点、工具节点、知识库节点、条件节点分别对应代码里的模型调用、工具执行、检索、路由 |
| Coze | 零代码、插件生态、快速发布 | 适合快速原型验证和非技术用户 |
| Dify | 开源企业级平台，支持复杂工作流和插件 | 适合专业开发者、企业应用、复杂业务逻辑 |
| FastGPT | 侧重知识库 / RAG 的平台 | 适合企业知识助手、智能客服 |
| n8n | 通用自动化平台，强调业务系统集成 | 适合邮件、CRM、数据库等业务流程自动化 |
| 混合开发 | 低代码验证想法，代码处理精细逻辑 | 实际工程里通常不是二选一，而是按阶段混用 |

## 🔑 关键要点

1. **低代码不是替代代码开发，而是补充。**
2. **平台适合快速验证，代码适合精细控制、扩展、版本管理和生产工程化。**
3. **可以把可视化节点映射回第四章代码概念：**
   - LLM 节点 ≈ `HelloAgentsLLM.think()`
   - 工具节点 ≈ `ToolExecutor`
   - 知识库节点 ≈ 检索能力
   - 工作流连线 ≈ Agent 的执行路径
4. **平台选型思路：**
   - 快速原型：Coze
   - 企业级复杂应用：Dify
   - 知识库问答：FastGPT
   - 业务自动化：n8n
5. **本章重点是“了解平台抽象”，不是深入平台运维。**

## 💻 实践记录
